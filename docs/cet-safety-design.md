# CET 儿童安全设计（Safety Guard）

Safety 是**独立系统级约束**，不是一句系统 Prompt。总设计见 [cet-tutor-design.md](cet-tutor-design.md)。

---

## 1. 目标

1. 拦截不适合儿童的输入/输出（色情、暴力、自伤、仇恨、危险活动、隐私诱问等）。
2. 限制模型角色：外教陪练，不扮演不当角色、不与儿童发展恋爱/暧昧关系。
3. 可审计、可人工复核（HITL，MVP-4）。
4. 对儿童展示温和提示，不暴露内部策略细节。

---

## 2. 在链路中的位置

```
所有用户输入 ──► Safety（入）──► Planner / Tutor / ...
所有模型输出 ──► Safety（出）──► 客户端
```

可选补充：MCP `child_safety_check`（与内置规则/模型集成，不互相替代责任）。

---

## 3. 分层策略

| 层 | 手段 | MVP |
|---|---|---|
| L0 规则 | 关键词/正则/年龄策略、主题白名单 | 1 |
| L1 分类模型 | 专用安全分类或 LLM JSON 判定 | 1 |
| L2 输出复查 | 对外教回复再检 | 1 |
| L3 HITL | 家长/老师复核队列 | 4 |
| L4 运营 | 管理台策略与事件查询 | 4 |

**禁止**仅依赖 Tutor Prompt 中的「你是儿童老师」。

**已落地（阶段 3c）：**

- L1/L2 模型调用失败或 JSON 非法 → **fail-closed**（`SOFT_BLOCK` / `L1_UNAVAILABLE`），禁止再默认 `ALLOW`。
- Tutor **输出先完整生成 → L2 闸门 → 再按块 SSE**，避免不安全 token 先泄漏到客户端。
- 事件 `detail_json` 写入 `policyVersion`（如 `cet-safety-v1`）；应用日志不含完整敏感原文。
- stream API 使用 `Flux.defer` + 有界调度器，JDBC/输入 Safety/同步 LLM 离开 event-loop。
---

## 4. 动作

| 动作 | 含义 |
|---|---|
| `ALLOW` | 放行 |
| `REWRITE` | 改写为安全表述（慎用，须再检） |
| `SOFT_BLOCK` | 拒本当轮，会话继续，提示换说法 |
| `HARD_BLOCK` | 会话 `SAFETY_BLOCKED`，通知家长（后期） |
| `ESCALATE` | 进入 HITL 队列 |

事件写入 `cet_safety_event`（类型、动作、turnId、策略版本）；**日志不含完整敏感原文**或仅存受限审计库。

---

## 5. 内容边界（摘要）

- 禁止：成人内容、详细暴力、违法教唆、自伤方法、血腥恐怖。
- 谨慎：宗教/政治争议 → 中性转移回学习主题。
- 隐私：不主动索取真实姓名住址学校电话；若孩子主动说，不复述传播。
- 人设：不可突破外教/导师教育边界。

细则实现期落为策略配置（库表或配置中心），版本号入审计。

---

## 6. 与人设 / 评测

- Safety **高于**人设风格；Coco/Tom 等均不可越界。
- 评测反馈须鼓励式，禁止羞辱性措辞（输出侧规则）。

---

## 7. Human-in-the-loop（MVP-4）

- 高风险 `ESCALATE` → 管理台/家长确认前暂停自动续聊。
- 家长可查看安全事件摘要（非原始敏感全文策略由合规定）。

---

## 8. 验收

1. 注入测试集：明显违规输入被 SOFT/HARD block。
2. 正常宠物/家庭主题高通过率。
3. 每次命中有 event + 策略版本。
4. 儿童 UI 无内部策略泄漏。
